# Open Label Auditor — 安疗标准食品搜索工具

Open Label Auditor is an AI Skill for Ingredient Verification and auditable food-label screening — a Clean Label-ready ingredient list checker for global product search that binds every verdict to the exact on-package quotation. Built-in presets cover the Medical Medium (Anthony William) framework, Gluten-Free, Vegan / Vegetarian, Clean Label, and custom rules with unit-price normalization. 面向商品搜索的配料表审核助手：逐条深度核验配料表、防隐性成分陷阱，内置美国医疗灵媒（Medical Medium / Anthony William，安东尼·威廉）安疗饮食（1–5 级）、无麸质食品、素食（Vegan / Vegetarian）与零添加预设。

中文核心说明：这是一个面向全球电商食品搜索的可审计 Skill。用户未说明购买或收货国家/地区时会先被询问，之后可以选择安疗、严格无麸质、素食或自定义规则；搜索结果默认必须完整抄录目标市场包装上的配料和食品添加剂、提供精确购买链接，并把商品页全部在售规格换算为当地币种每500g单价后从低到高排列。含明确排除成分的商品不会进入结果；同一页面的不同配方选项会逐项核验，合格选项原名会标在商品名称后。仓库内的本地审计与 Demo 不联网，也不需要 API Key。

## Why auditable label screening?

| Ordinary LLM shopping answer | Open Label Auditor |
|---|---|
| Treats a title such as “clean” or “gluten-free” as proof | Requires evidence tied to the exact SKU and package version |
| May miss hidden terms such as `植物蛋白` or wheat inside `酿造酱油` | Returns `WARN` or `FAIL` with the matched label quotation |
| Often compares sticker prices instead of total guaranteed weight | Parses multi-packs and reports normalized `CNY/500g` |
| May invent a unit price for gifts, drained weight, or approximate weight | Withholds the calculation and requests manual verification |

```text

        v

        |
        v

        |
        v
Every formula option --------> exact-SKU label evidence
        |
        v

```

## Quickstart: under three minutes

Python 3.10 or newer is required. No runtime dependencies, API key, or live marketplace access are needed for the bundled demo.

```bash
git clone https://github.com/YOUR_ORG/codex-anliao-food-search.git
cd codex-anliao-food-search
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
python -m pip install -e .
label-audit --demo
```

The module form works without installing the CLI entry point:

```bash
python -m src.demo
```

Reproduce the checked-in golden benchmark with one command:

```bash
python evals/run_eval.py
```

## Built-in presets

| Preset | Variants | Intended use |
|---|---|---|
| `medical-medium` | cumulative `level_1` through `level_5`; optional Bonus/additional exclusions | Operational transcription of *Cleanse to Heal* pp. 70–72 for users who explicitly choose this framework |
| `gluten-free` | `strict` | Rejects explicit gluten sources and warns on ambiguous Chinese-label ingredients |
| `vegetarian` | `vegan`, `lacto_ovo`, `pescatarian` | Screens animal-derived ingredients for three common vegetarian modes |
| `clean-label` | `strict` | Screens selected additives and warns when the ingredient list exceeds the configured threshold |
| custom exclusions | user-supplied terms layered onto a preset | Adds product-specific hard exclusions without editing a preset |

The Medical Medium preset represents claims from the cited source. It is not medical advice and is not presented as established medical evidence. See [`references/medical-medium-levels.md`](references/medical-medium-levels.md).

## Codex and OpenAI Agents SDK integration

The repository keeps both integration artifacts at standard top-level locations:

- [`SKILL.md`](SKILL.md) contains the Codex workflow, evidence requirements, preset-selection gate, and mandatory output contract.
- [`agents/openai.yaml`](agents/openai.yaml) contains user-facing metadata and allows implicit Codex invocation.

Install or copy the repository into a Codex skills directory and invoke `$anliao-food-search`; Codex reads `SKILL.md` and the metadata file from these locations. A programmatic OpenAI Agents SDK integration can load the same instructions directly:

```python
from pathlib import Path
from agents import Agent

skill_instructions = Path("SKILL.md").read_text(encoding="utf-8")
agent_metadata = Path("agents/openai.yaml").read_text(encoding="utf-8")

agent = Agent(name="Open Label Auditor", instructions=skill_instructions)
# agent_metadata can be passed to your own UI/orchestration layer.
```

`agents/openai.yaml` is Codex UI metadata; the Agents SDK does not automatically interpret that YAML file.

## Safety and evidence boundary

- The project does not log into shopping accounts, store cookies or credentials, or bypass platform restrictions.
- A keyword match cannot prove that a label belongs to a purchase link. Live shopping results must bind evidence to the exact platform, seller, SKU, flavor, size, and package version.
- Prices, stock, and formulas change. Live reports must include a verification date, and serious allergy or medical restrictions require checking the delivered package again.
- The deterministic rules support review; they do not replace clinical advice, regulatory allergen guidance, or manufacturer confirmation.
